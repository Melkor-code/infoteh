# Как мы работаем

Этот текст для тех, кто почти не пользовался GitHub и не писал большие программы. Термины объяснены на месте.

## Три слова, которых хватит

**Репозиторий** — папка проекта, которая лежит на сайте GitHub, а не только на одном компьютере. Жюри откроет её по ссылке.

**Ветка** — отдельная копия этой папки. Наша рабочая копия называется `arena/01a0da4d-infoteh`. Главная копия называется `main`. Сейчас рабочая копия живая, главная пустая. Так устроен этот чат с помощником: писать можно только в рабочую ветку.

**Коммит** — сохранённая точка «вот что изменилось и зачем». Как сохранение в игре, только с подписью. Делать коммиты и отправлять их на GitHub будет помощник в чате. Вручную это делать не нужно.

## Что делает координатор

Координатор — владелец этого чата. Его работа не в кнопках GitHub.

1. Принимает решения: какие аппараты, что успеваем, что выкидываем.
2. Приносит в чат куски работы одногруппников: текст, картинки, замечания.
3. Открывает ссылку на ветку и проверяет, что там правда лежит то, о чём договорились.
4. Следит за датами. После 5 октября новые идеи не добавляем.
5. В день сдачи, и только тогда, нажимает на GitHub кнопку слияния в `main`, чтобы жюри не открыло пустую страницу. До этого дня кнопку не нажимать: иначе главная страница устареет, а новая работа останется в ветке.

Не нужно ставить Git, учить команды и создавать второй репозиторий.

## Что делают остальные трое

Они тоже не коммитят в этот репозиторий, пока координатор явно не разрешит. Два человека, которые одновременно правят одну сцену, легко затирают работу друг друга. Пока канал один: сделал кусок — отдал координатору — координатор принёс его в чат.

Роли:

- Технический следит за формулами, паспортами и тем, чтобы число нельзя было перепутать с выдумкой.
- Креативный отвечает за то, как это выглядит: местности, камеры, ролик, слайды. Ролик снимается с готовой программы, не рисуется нейросетью.
- Четвёртый собирает управление, телеметрию, отчёт и файл `.exe` на Windows. Нейросеть можно использовать как черновик текста и однотипного кода. Коэффициенты аппаратов она не придумывает.

Кто за какой вопрос отвечает на защите — тот и владелец модуля. Нельзя выйти и сказать «это написала сеть, я не смотрел».

## Как просто посмотреть проект

1. Открыть https://github.com/Melkor-code/infoteh/tree/arena/01a0da4d-infoteh
2. Убедиться, что вверху написано имя ветки `arena/01a0da4d-infoteh`, а не `main`.
3. Если нужно скачать папку: зелёная кнопка Code → Download ZIP.

Этого достаточно. Команду `git clone` учить не надо.

## Если править проект с другого компьютера

Это обычная папка Godot, не закрытый формат этого чата. Другая нейросеть на ноутбуке одногруппника сможет открыть те же файлы и причесать код, если ей дать эту ветку, а не пустую главную страницу.

Чтобы не разъехаться:

- Godot 4.7, обычная версия, не .NET. Режим Compatibility не менять: на нём потом собирается `.exe`.
- Не ставить чужие плагины и не подменять расчёт полёта библиотекой аэродинамики. Формулы живут в `scripts/flight_model.gd` и `scripts/quadrotor.gd`.
- Паспортные числа не выдумывать и не округлять. Новые модели — файл в `data/vehicles/`, не новая сцена.
- Не называть переменную `signal`: в Godot это служебное слово, проект из-за этого не запускается.
- Не возвращать `class_name` рядом с `preload` того же имени: редактор пишет предупреждения и путает тип.
- В один день не править `scripts/app.gd` и отсюда, и с ноутбука. Это самый большой файл, правки затрут друг друга. Физику лучше оставлять этому чату, картинки и текст — ноутбуку, либо договариваться, кто сегодня владеет файлом.
- Перед правкой скачать свежий ZIP или подтянуть ветку. После правки принести файлы сюда или отправить в ту же ветку, не в `main`.

## Чего не делать

- Не создавать новый репозиторий «чтобы было удобнее». Отчётный уже есть.
- Не загружать `.exe` внутрь истории папки. Готовая программа в день сдачи ляжет отдельным Release — это полка для файла, не для исходников.
- Не копировать в проект чужой код с лицензией GPL (ArduPilot, Betaflight, FlightGear). Идеи можно пересказывать своими словами.
- Не подменять демонстрацию сгенерированным видео.
